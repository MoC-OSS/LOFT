LOFT

Open source · TypeScript · MIT

The LLM side of your chat backend, handled.

LOFT is a TypeScript library that sits between your API and the model. Sessions, chat history, prompts, middleware, tool calls and rate limits are wired once, then each chat turn is a loft.chat.generate() call.

    Swap per request, too

    Register several providers, then pick one for a single call. temporaryLlmName and temporaryManifestName apply to that call only. They are not saved on the session.

    To move a session to another model for every later turn, change its currentLlmName with loft.chat.updateSessionSettings(). Either way, a conversation can change models between turns.

    Prompts are data, not deploys.

    Requests arrive every 1 to 3 seconds, and now and then storage does not answer a refresh. Simulated TTL: 10 s. In your app it is cacheExpirationTime, in milliseconds. You set it; there is no default. The README quickstart uses 60_000; the example apps default to 3600000. LOFT checks the cache when a request arrives, so the first request after expiry reloads the manifest.

    30 s agonow

      If a refresh fails, the app keeps answering

      When storage is unreachable or the new manifest does not validate, LOFT keeps serving the cached manifest, extends it by 5 minutes, and tries to write the error as JSON to errorPath in the same storage. Try it: switch to JSON, break the file (delete a brace, or remove modelPreset from an entry), save it, and watch the next refresh after the ring runs out. The simulation shows the 5-minute extension as 15 s.

      Dynamic prompts

      The manifest holds the prompt. A computer can still rewrite it for each request, for example to add the date or something from the session. It receives the manifest's system message and returns the one the model gets.

      loft.ts
      loftConstructor.registerGMComputer(
  'support-bot',   // manifest name
  'gpt-4o-mini',   // llm name
  async (_ctx, prompt, _modelPreset) =>
    prompt.content + '\nCurrent time: ' + new Date().toISOString()
);

      Based on examples/express-full/src/loft.ts. The manifest guide covers computers in full.

      Three sections in the file

      All three are required, even when empty.

      • llmManifestsPer manifest name and LLM name: systemMessage and modelPreset. Used by generate().
      • promptsNamed prompt text per LLM name. Read in middleware or a computer with ctx.getPrompt(promptName, llmName).
      • aiTasksSame shape as llmManifests, for one-off calls with no chat history: ctx.aiTask(llmName, aiTaskName, content).

      Chapter 6 · Beyond one chat

      Beyond one chat.

      The same building blocks run multi-agent graphs, collect structured data over several turns, call tools and run one-off AI tasks.

      Several agents, one orchestrator

      Each agent is a node that makes one generate() call with its own manifest. A transitionResolver decides where the run goes next: one node (SINGLE), several at once (FAN_OUT), or nowhere, when the node has no transitions.

      By default, every LoftAgentNode stores its answer in the SharedContext under its name, so a later node sees what the earlier ones said. Pick a pattern and watch it run on the restaurant router from the express-agents example.

      Collect structured data over several turns

      Register a Focus with typed fields and LOFT adds a prompt and three tools to generate(): update_<name>_focus, confirm_<name>_focus and classify_<name>_focus. The model fills fields as the user talks. Field types are STRING, NUMBER, BOOLEAN, ENUM and DATE, and a field can carry its own validate function.

      After each call, read result.focusStatus. When every required field is filled, ready is true and filled holds the values. They are returned once and then cleared from the store.

      focus.ts
      const pizzaOrder: Agent.Focus = {
  agentName: 'pizza-order',
  prompt: 'Collect pizza order details from the customer',
  fields: [
    {
      key: 'size',
      type: Agent.FocusFieldType.ENUM,
      values: ['small', 'medium', 'large'],
      required: true,
      description: 'Pizza size'
    },
    {
      key: 'quantity',
      type: Agent.FocusFieldType.NUMBER,
      required: true,
      description: 'Number of pizzas (1-10)',
      validate: (v) => {
        const n = Number(v);
        return n >= 1 && n <= 10 ? true : 'Quantity must be between 1 and 10';
      }
    }
    // pizza_type, delivery_address, payment_method ...
  ],
  // required by the type; graphs route on the node's onFocusComplete
  onComplete: {
    type: Agent.FocusActionType.TRANSITION,
    target: 'done'
  }
};

loft.registerFocus('pizza-order', pizzaOrder);

const result = await loft.chat.generate({
  sessionId,
  directMessages,
  focusAgent: 'pizza-order'
});

if (result.focusStatus?.ready) {
  await saveOrder(result.focusStatus.filled);
}

      Tools from any MCP server

      Connect an MCP client and LOFT offers its tools to the model on every generate() call. When the model asks for a tool, LOFT runs it, appends the result and calls the model again, until the model answers without a tool call.

      An optional interceptor runs instead of the plain call for one tool, so you can add context, check access or return your own result. The loop is capped: by default 10 LLM calls per generate(), so at most 9 rounds of tools.

      mcp.ts
      const chatConstructor = new ChatConstructor(
  sessionRepo,
  chatHistoryRepo,
  undefined,
  undefined,
  // the values shown are the defaults
  { mcp: { maxCallsPerGenerate: 10, toolCacheTtl: 60_000 } }
);

// after new LoftConstructor(..., chatConstructor); client connected
await chatConstructor.useMcpClient('orders', client);

// adds a value LOFT knows; the server tool must declare customerId
chatConstructor.registerToolInterceptor(
  'get_order',
  async ({ ctx, toolRequest, executeToolFn }) =>
    executeToolFn({
      params: {
        ...toolRequest.params,
        arguments: {
          ...toolRequest.params.arguments,
          customerId: ctx.session.ctx.customerId
        }
      }
    })
);

      One-off AI tasks

      An AI task is a single model call with no chat history, no middleware and no tools. Define it in the aiTasks section of the manifest and call it with ctx.aiTask(llmName, taskName, content) from middleware, prompt computers or tool interceptors. It is not a method of loft.chat.

      A string content is sent as a user message; the system message comes from the manifest.

      manifest.json
      "aiTasks": {
  "classify-intent": {
    "gpt-4o-mini": {
      "systemMessage": "Classify the user's intent. Reply with one word.",
      "modelPreset": { "model": "gpt-4o-mini", "temperature": 0, "max_tokens": 20 }
    }
  }
}
      middleware.ts
      chatConstructor.registerBeforeGenerateMiddleware(
  'classify',
  async (ctx, payload, chain) => {
    const userText = lastUserText(payload); // your helper

    // one model call: no history, no middleware, no tools
    const result = await ctx.aiTask(
      'gpt-4o-mini',     // a registered LLM name
      'classify-intent', // a key under aiTasks in the manifest
      userText
    );
    // result.topChoice.content holds the answer, as in generate()

    chain.next();
    return payload;
  }
);

        Running it in production

        Four things you configure once. Open any of them.

        Rate limits and retries per modelQueue, token bucket, fixed retry delay

        Each model gets a GenerateCallManager: one queue that runs one request at a time, a token-bucket rate limiter and retries. LlmTokenRateLimiter takes newTokensPerSecond, newRequestsPerSecond, maxTokens, maxRequests and maxAwaitSeconds. A call that would wait longer than maxAwaitSeconds fails with LlmCallManagerLongAwaitError.

        A failed call is tried up to retryAttemptsLimit times in total, with a fixed retryDelay between attempts. There is no exponential backoff, and an aborted call is not retried. Adding a high-priority task to a queue that already holds highPriorityTasksLimit tasks throws TooManyHighPriorityTasksError.

        new GenerateCallManager('gpt-4o-mini', {
  highPriorityTasksLimit: 10,
  retryDelay: 1000,
  retryAttemptsLimit: 3
}, callStrategy);
        Context-window croppingSend only the newest messages to the model

        Pass llmContextWindow to generate() and only about that many of the newest messages go to the model. Cropping never separates a tool call from its result, so it can keep a few more than you asked for. 0, or leaving it out, sends everything.

        To crop your own way, pass a LlmContextWindowCropper as the fourth ChatConstructor argument.

        await loft.chat.generate({
  sessionId,
  directMessages,
  llmContextWindow: 50
});
        Tracing with Langfuse or your own tracerThe span tree above, sent where you want it

        Pass a LangfuseTracer as the fourth LoftConstructor argument, or implement Strategy.Tracer.TracerFactory for your own backend. Without one, LOFT uses a no-op tracer. generate() flushes the tracer before it returns.

        // npm install langfuse@^3 (optional peer dependency)
const tracer = new LangfuseTracer({
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!
});

new LoftConstructor(
  { logLevel: Interface.LogLevel.INFO },
  manifestManagerConstructor,
  chatConstructor,
  tracer
);
        Graceful shutdownLet running requests finish, then stop

        loft.shutdown() waits for the requests that are already running and stops the rate-limiter timers. From then on, new calls on loft.chat throw ShutdownError. loftConstructor.gracefulShutdown() flushes what the tracer still holds.

        process.on('SIGTERM', async () => {
  await loft.shutdown();
  await loftConstructor.gracefulShutdown();
  process.exit(0);
});

        Next: the program that runs one turn.

        Run this with OPENAI_API_KEY and DATABASE_URL set. The next generate() on the same session loads the saved messages and sends them with the new one.

        index.ts
        import 'reflect-metadata';

import { ChatConstructor, FsRepositoryConstructor, LoftConstructor, ManifestManagerConstructor } from '@moc-global/loft';
import {
  ChatHistoryPostgresDialect,
  ChatHistoryRepositoryConstructor
} from '@moc-global/loft-chat-history-pg-repository';
import { Interface, NativeCallManagerStrategy, Type } from '@moc-global/loft-definitions';
import { GenerateCallManager, LlmTokenizer, LlmTokenRateLimiter } from '@moc-global/loft-llm-call-manager';
import {
  OpenAiCallStrategy,
  OpenAiLoftStrategy,
  OpenAiRequest,
  OpenAiResponse
} from '@moc-global/loft-openai-strategy';
import { SessionPostgresDialect, SessionRepositoryConstructor } from '@moc-global/loft-session-pg-repository';
import { Pool } from 'pg';

async function main() {
  const pool = new Pool({ connectionString: process.env.DATABASE_URL });

  const loftConstructor = new LoftConstructor(
    { logLevel: Interface.LogLevel.WARN },
    new ManifestManagerConstructor(new FsRepositoryConstructor(), {
      manifestPath: 'manifest/manifest.json',
      errorPath: 'manifest/errors/error.json',
      cacheExpirationTime: 60_000
    }),
    new ChatConstructor(
      new SessionRepositoryConstructor(new SessionPostgresDialect({ pool }), { schema: 'loft_session' }),
      new ChatHistoryRepositoryConstructor(new ChatHistoryPostgresDialect({ pool }), { schema: 'loft_chat_history' })
    )
  );

  // The call manager queues, rate-limits and retries the calls to one model
  const callManager = new GenerateCallManager<OpenAiRequest, OpenAiResponse>(
    'gpt-4o-mini',
    { highPriorityTasksLimit: 10, retryDelay: 1000, retryAttemptsLimit: 3 },
    new OpenAiCallStrategy(
      process.env.OPENAI_API_KEY!,
      new LlmTokenRateLimiter({
        newTokensPerSecond: 50_000,
        newRequestsPerSecond: 100,
        maxTokens: 2_000_000,
        maxRequests: 500,
        maxAwaitSeconds: 300
      }),
      new LlmTokenizer()
    )
  );
  await loftConstructor.registerLlmStrategy(
    'gpt-4o-mini',
    new OpenAiLoftStrategy({ llmName: 'gpt-4o-mini' }, new NativeCallManagerStrategy(callManager))
  );

  const loft = loftConstructor.getInstance();
  const session = await loft.chat.createSession({
    currentLlmName: 'gpt-4o-mini',
    currentManifestName: 'assistant',
    ctx: {}
  });
  const result = await loft.chat.generate({
    sessionId: session.id,
    directMessages: [
      {
        sessionId: session.id,
        role: Type.LLM.UnifiedMessageRole.user,
        author: 'user',
        content: [{ type: 'text', text: 'What can you help me with?' }],
        llmName: 'gpt-4o-mini',
        manifestName: 'assistant',
        ctx: {},
        llmIgnore: false
      }
    ]
  });

  for (const part of result.messages.llmResponse.topChoice.content) {
    if (part.type === 'text') console.log(part.text);
  }
  // Store the user message and the reply; generate() itself stores nothing
  await result.messages.save();

  await loft.shutdown();
  await pool.end();
}

main();

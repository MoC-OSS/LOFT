`GeminiCallStrategy` streams inside `generate()` when LOFT passes an `onEvent` sink in the call options. The request is sent with `generateContentStream`, the first candidate's text reaches the sink as it arrives (its thought summaries as reasoning), and `generate()` resolves with the same `GenerateContentResponse` the request returns without streaming, so `formatToUnifiedLLMResponse`, `extractUsedTokens`, function calls and thought signatures work unchanged. Function-call arguments, thought signatures, code, inline data and the parts of other candidates are never sent to the sink; they only report activity. A finish on `SAFETY` and a blocked prompt are returned, not thrown. When a filter blocks the reply (`SAFETY`, `RECITATION`, `SPII` or `PROHIBITED_CONTENT`), the candidate has no content, as without streaming; the text already sent to the sink cannot be taken back, so the chat's `finish` event carries the empty text with `textReplaced`. An error in the middle of the stream rejects with the SDK's error. An abort of the call's signal rejects with an `AbortError`, as it does without streaming, even when the last chunk had already arrived. A stream that ends before every candidate finished, between events or inside one, without a blocked prompt, rejects with the SDK's `ApiError` with status 502 and the message "No HTTP error occurred: the stream ended before the model finished its reply" (the SDK's own error, if any, as its `cause`), so the call manager may retry it; once every candidate has finished, a stream cut short resolves with what arrived. An error object the SDK receives split across network reads also rejects with that 502, as the SDK does not recognise it, unless every candidate had already finished, when the reply stands. An empty text part without a thought signature is left out of the merged parts, unless the candidate has no other part. The provider logs a failed streamed call with the error's class, status, `type` and `code` only: the provider's own failure log never includes the error message. The call manager and the chat still log the error as before. Gemini sends the usage on many chunks as a running total, so each `usage` event replaces the one before. Without `onEvent` the request is sent as before (see the usage note below).

`GeminiCallStrategy` takes an optional, experimental last constructor argument, `GeminiStrategyOptions`, with `streaming` (default `true`): `false` never streams, even when LOFT passes `onEvent`.

The unified usage of a Gemini response now also carries `reasoningTokens` (the response's `thoughtsTokenCount`, when it has one) and `finishReason` (the first candidate's), for streamed and non-streamed calls alike.

Deprecated, with nothing removed now: `GeminiCallStrategy.generateStream` and `extractContentFromChunk`, the `generateStream` method of `GeminiLoftStrategy` and `GeminiStream`. Use `chat.generate({ onEvent })` instead. They are removed in the next major release.
